# Licence layers for review

This outline identifies assets in the package and the questions to resolve before choosing release terms.

## Code

The builder, verifier, loader and simulator are software. Who holds the rights in each component? Which
software licence can cover it? Which dependency notices and source attributions must accompany a copy?

## Numeric model outputs

Predictions and collected call observations are subject to the terms applicable to each model provider.
Which version of the terms governed the collection? Which terms cover vectors, reported choices, token
counts, costs and latency? Which model and benchmark combinations can be shared openly or through gated
access? What evidence supports each clearance decision, and what restrictions apply to downstream reuse?

## Benchmark-derived structure

Request identifiers, field layout, option counts, grouping and fold assignments derive from benchmarks.
Which benchmark terms govern each structural table or component? Do those terms permit the intended
redistribution of identifiers and structure? What attribution, access restrictions or separate permissions
are required for each benchmark?

## Locally derived labels

Release tiers distribute neither benchmark rows nor labels. Holders can use their own rows to reconstruct
accepted option positions and judged flags in a private copy. How may a holder obtain the matching rows?
Which benchmark terms govern local derivation, storage and use of labels? Which aggregate evaluation
results may the holder publish, and what attribution would that require?
